
# Part 2: Chef's Menu Manager (MAST5112)

## Important Disclaimer

> ⚠ **Please read this first.**

This guide has been created to help you understand the requirements and quality expectations for **Part 2** of the Chef's Menu Manager Portfolio of Evidence (PoE).

The checklist below is aligned to the assessment rubric and is intended to help you prepare a stronger submission. However:

-   It does **not** represent the exact marking allocation used during assessment.
-   Individual checklist items should **not** be interpreted as carrying specific marks.
-   Meeting every item does **not** automatically guarantee a particular mark.
-   Final marks will be awarded using the official rubric and the overall quality of the completed application.

Use this guide to help you understand:

-   What must be submitted.
-   What excellent work looks like.
-   Common mistakes that cost marks.
-   Professional software development practices expected from developers.

----------

# Section 2: What Excellent Work Looks Like

The following checklist is based on the standards expected from students aiming to achieve the highest rubric category.

----------

# 2.1 Build the User Interface (30 Marks)

### Strong submissions typically demonstrate:

✓ Clear application title

✓ Layout reflects the design planned in Part 1

✓ Appropriate React Native components used

✓ Clear labels for all user inputs

✓ Readable text throughout the application

✓ Consistent spacing and alignment

✓ Appropriate font sizes

✓ Appropriate colour choices

✓ Logical grouping of related information

✓ Professional appearance

✓ Layout is easy to use on a mobile device

✓ User can immediately understand how to use the application

✓ Interface feels complete rather than experimental

----------

# 2.2 Capture Menu Information (25 Marks)

The chef must be able to capture:

✓ Dish Name

✓ Description

✓ Course

✓ Price

### Strong submissions typically demonstrate:

✓ Appropriate input controls selected

✓ Data entry process is simple and intuitive

✓ Information is captured accurately

✓ Save functionality works consistently

✓ Input values are validated

✓ Invalid information is prevented where possible

✓ Interface guides the user during data entry

✓ Data entered by the user is stored correctly

----------

# 2.3 Display Menu Items (25 Marks)

### Strong submissions typically demonstrate:

✓ Menu items are stored in an array

✓ Multiple menu items can be added

✓ Multiple menu items can be displayed

✓ Newly added items appear immediately

✓ Display updates automatically

✓ Information is presented clearly

✓ FlatList (or equivalent list display) functions correctly

✓ Records remain visible after additional entries are added

✓ Information is arranged in a professional manner

✓ The display remains readable as the list grows

----------

# 2.4 Improve the User Experience (20 Marks)

### Strong submissions typically demonstrate:

✓ Validation for required fields

✓ Helpful error messages

✓ Error messages clearly explain what is wrong

✓ Success message shown when a menu item is added

✓ Empty-state message shown when no menu items exist

✓ Consistent layout throughout the application

✓ Clear user guidance

✓ Simple and intuitive interactions

✓ Reliable feedback for user actions

✓ User-friendly experience

✓ Polished overall presentation

----------

# Section 3: Common Reasons Students Lose Marks

The following issues frequently result in lower marks.

Avoid these mistakes.

----------

## User Interface Issues

✗ Poor spacing between components

✗ Misaligned interface elements

✗ Difficult-to-read text

✗ Missing labels

✗ Poor component selection

✗ Cluttered screen layout

✗ Inconsistent styling

✗ Interface does not resemble planned design

✗ Interface appears unfinished

----------

## Data Capture Issues

✗ Missing required fields

✗ Incorrect input controls

✗ Save button does not work

✗ Information not captured correctly

✗ Invalid values accepted without validation

✗ Application crashes during data entry

✗ Incomplete functionality

----------

## Display Menu Item Issues

✗ Only one item can be stored

✗ New entries overwrite existing entries

✗ Menu items do not display correctly

✗ Information missing from displayed records

✗ FlatList does not update correctly

✗ Data disappears unexpectedly

✗ Display formatting makes items difficult to read

----------

## User Experience Issues

✗ No validation implemented

✗ Error messages are unclear

✗ No feedback provided when actions occur

✗ User does not know if an item was saved successfully

✗ No empty-state message when list is empty

✗ Inconsistent user experience across the application

✗ Interface is confusing to navigate

----------

## Video Demonstration Issues

✗ Demonstration is too short

✗ Required features are not shown

✗ Validation not demonstrated

✗ Menu item creation not demonstrated

✗ Display functionality not demonstrated

✗ Video link does not work

✗ Audio or visuals make the demonstration difficult to follow

----------

## GitHub Issues

✗ Single commit containing the entire project

✗ Meaningless commit messages

✗ Missing project files

✗ Code pushed after the submission deadline

✗ Repository contains unnecessary files

✗ Repository appears disorganised

----------

# Section 4: Professional Software Development Checklist

While these items may not always appear as individual rubric criteria, they are important indicators of good software development practice and contribute to the overall professionalism of your submission.

----------

# GitHub Best Practices

✓ Repository is organised

✓ Multiple commits made throughout development

✓ Commit messages describe the work completed

✓ Development progress can be seen through commit history

✓ Project structure is logical and easy to navigate

### Examples of good commit messages

✓ Created menu item capture form

✓ Added state management for menu items

✓ Implemented form validation

✓ Added FlatList menu display

✓ Improved application styling

✓ Updated README documentation

### Examples of poor commit messages

✗ Update

✗ Changes

✗ Final

✗ Assignment

✗ Done

----------

✓ Project overview

✓ Features implemented

# Final Advice

A student can successfully meet the minimum requirements for Part 2 with a simple application that:

✓ Captures menu information

✓ Validates input

✓ Stores menu items in an array

✓ Displays menu items dynamically

However, students aiming for the higher achievement categories should focus on:

✓ Presentation

✓ Usability

✓ Validation

✓ User feedback

✓ Consistency

✓ Code quality

✓ GitHub professionalism

✓ Documentation quality

✓ A well-structured video demonstration

Remember:

> **Part 2 is not the completed Chef's Menu Manager. It is a working prototype that forms the foundation for the Final PoE. Focus on creating a reliable, professional, and user-friendly application that can be extended with additional features later in the project.**
